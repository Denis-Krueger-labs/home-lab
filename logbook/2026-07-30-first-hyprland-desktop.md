**Date:** 2026-07-30  
**VM ID:** 111

**Result:** Successful

## Objective

The objective was to extend the existing minimal NixOS installation with a functional Hyprland desktop environment.

The desktop was assembled from individual Wayland components rather than installing a complete desktop environment such as KDE Plasma or GNOME.

This approach was chosen to gain practical experience with:

- Wayland compositors
- Tiling window management
- User-session management
- Application launchers
- Graphical file managers
- Status bars
- Desktop theming
- Wallpaper management
- Hyprland Lua configuration
- Declarative package installation
- Graphical session autostart
- Future Quickshell integration

The resulting environment will serve as the development base for a later NixOS installation on a Dell XPS 16 9640.

The system was rebuilt after package changes using:

    sudo nixos-rebuild switch

This made the selected applications part of the declared operating-system state.

## Hyprland System Integration

Hyprland and UWSM were enabled through the NixOS configuration.

The relevant configuration includes:

    programs.hyprland = {
      enable = true;
      withUWSM = true;
    };

    programs.uwsm.enable = true;

    security.polkit.enable = true;
    services.dbus.enable = true;

    xdg.portal = {
      enable = true;
      extraPortals = with pkgs; [
        xdg-desktop-portal-gtk
      ];
    };

Enabling Hyprland through the NixOS module provides the compositor, session definitions and required system integration.

UWSM starts Hyprland as a managed user session rather than as a single unmanaged process.

## Starting the Hyprland Session

The initial attempt used the following session name:

    uwsm start hyprland-uwsm.desktop

UWSM reported that this entry could not be found.

The available compositor entries were inspected using:

    uwsm select

Two entries were presented:

- Hyprland
- Hyprland (uwsm-managed)

The UWSM-managed entry was selected as the default.

The saved session was then started with:

    uwsm start default

Hyprland launched successfully inside the Proxmox graphical console.

The first Hyprland session displayed the generated default wallpaper and an autogenerated-configuration warning.

Kitty was opened using:

On the physical keyboard, `Super` corresponds to the Windows key.

The successful launch of Kitty verified the complete graphical chain:

    NixOS
    → UWSM
    → Hyprland
    → Kitty

Multiple Kitty windows were opened to test dynamic tiling.

The following behavior was verified:

- New windows were tiled automatically.
- Focus could be moved using directional keybindings.
- The focused window could be closed.
- Windows could be toggled between tiled and floating modes.
- Workspaces could be selected using number keys.

## Hyprland Lua Configuration

The installed Hyprland version uses a Lua configuration file:

    /home/labadmin/.config/hypr/hyprland.lua

This differs from older Hyprland versions that commonly used `hyprland.conf`.

The generated configuration contained an autogenerated marker.

The marker was changed from:

    autogenerated = true

to:

    autogenerated = false

After reloading the configuration, the warning banner disappeared.

The configuration was reloaded using:

    hyprctl reload

## Waybar Installation

Waybar was added to the NixOS package list and tested manually inside the graphical Hyprland session.

Running Waybar from an SSH session resulted in:

    Gtk-WARNING: cannot open display

This occurred because the SSH shell was not attached to the active Wayland display.

Waybar was therefore tested from Kitty inside Hyprland.

The first launch used Waybar's packaged default configuration.

The default configuration attempted to load modules intended for other environments, including Sway-specific modules and hardware sensors that were not available inside the VM.

These warnings did not indicate a Hyprland failure.

## Waybar Autostart Issue

An initial attempt used:

    hl.spawn_once("waybar")

The current Hyprland Lua API did not provide `spawn_once`.

This caused Hyprland to enter emergency mode because the configuration could not be evaluated.

Emergency mode retained a small set of rescue bindings, allowing Kitty to be opened and the configuration to be repaired.

The invalid line was removed.

Autostart was instead configured through the Hyprland start event.

The working structure is:

    hl.on("hyprland.start", function()
      hl.exec_cmd("hyprpaper")
      hl.exec_cmd(
        "waybar -c /home/labadmin/.config/waybar/config.jsonc " ..
        "-s /home/labadmin/.config/waybar/style.css"
      )
    end)

After restarting the session, Waybar launched automatically.

## Wallpaper Preparation

A custom subway illustration was selected as the desktop wallpaper.

The final wallpaper resolution is:

    3840 × 2400

This matches the native 16:10 resolution of the Dell XPS 16 9640.

A smaller 1280 × 800 copy was also prepared for the Proxmox VM.

The VM version reduces unnecessary scaling between:

- the wallpaper
- the 1280 × 800 virtual display
- the Proxmox noVNC browser console

The image still appears somewhat softer inside Proxmox because noVNC compresses and rescales the graphical output.

The VM is therefore treated as a layout and functionality test environment rather than an accurate wallpaper-quality preview.

## Hyprpaper Configuration

The first Hyprpaper configuration used an older syntax based on `preload` and `wallpaper` directives.

Hyprpaper started but reported:

    Monitor Virtual-1 has no target

The current Hyprpaper version required a wallpaper block.

The working configuration is stored at:

    /home/labadmin/.config/hypr/hyprpaper.conf

It assigns the wallpaper to the Proxmox display:

    wallpaper {
        monitor = Virtual-1
        path = /home/labadmin/Pictures/mori-wallpaper-vm.png
        fit_mode = cover
    }

    splash = false

The monitor name was verified through Hyprland.

Hyprpaper was then launched successfully.
